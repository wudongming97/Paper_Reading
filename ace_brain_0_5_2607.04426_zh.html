ACE-Brain-0.5：把“看、想、动、检查”接进同一个具身大脑

ACE-Brain Team · arXiv:2607.04426 v1 · 2026-07-05

一句话结论：ACE-Brain-0.5 的目标不是只做一个会输出动作的 VLA，而是把空间感知、任务规划、导航/操作、执行进度检查放进同一个 8B 具身模型。它用 SSR+ 训练：先继承 ACE-Brain-0 的空间底座，再分别训练任务专家、合并权重，最后用少量混合数据重新校准不同输出接口；“自我改进”则暂时主要靠外部记忆与 oracle 纠错的数据飞轮，而不是让机器人现场自主改写模型权重。

先补背景

  • 具身智能需要一个闭环。机器人应当看懂环境、决定下一步、执行动作，再判断自己是否真的更接近目标；只会从图像直接输出动作还不够。
  • VLA 擅长“动”，但往往不擅长解释与检查。视觉—语言—动作模型把画面和指令映射成控制量，适合低层执行，却常缺少显式空间推理、长程分解和进度评估。
  • 机器人 agent 擅长编排，却不一定共享表征。它可以把规划器、工具和专家串起来，但各模块各学各的，难以成为一个统一的机器人表征。
  • 空间理解是作者选择的共同底座。找物体、判断可抓取区域、导航避障、估计任务完成度，都依赖“物体在哪里、相互如何变化”的空间状态。

问题：能力拼在一起，为什么容易失效？

  • 任务不只不同，输出语言也不同。grounding 要输出框、掩码或坐标；导航要输出离散动作；操作要输出连续动作块；监控要输出进度数值。
  • 直接混训会产生接口干扰。模型可能仍然“知道”答案，却在该给坐标时输出解释文字，或在该给动作时沿用另一个任务的格式。
  • 完全分开训练又无法形成统一大脑。每个专家在本任务上很强，但部署时仍要靠外部系统协调，不能自然共享空间与任务状态。
  • 前作 ACE-Brain-0 仍偏理解。它已把空间智能作为跨自动驾驶、无人机与机器人操作的共同脚手架，但没有统一的动作接口与自我监控能力。

论文的主张不是取消所有外部系统，而是把闭环中的核心认知能力尽量收拢到一个共享表征中。

核心想法：一个共享状态，四类直接输出

  • LLM Decoder 形成共享具身状态。图像、多视角画面或视频先经视觉编码器，和语言指令、可选本体状态一起输入 LLM，得到当前场景与任务的高层上下文。
  • 空间感知负责“东西在哪、能做什么”。模型自回归输出目标框、掩码、空间点位及 affordance（物体可被抓、推或放置的区域）。
  • 决策负责“接下来分几步做”。高层任务被生成成自然语言子目标，例如先找到杯子、再移动到台面、最后抓取。
  • 具身交互负责“实际怎么动”。导航输出离散动作；操作交给专门的 flow-matching Action Expert 生成连续动作块。
  • 自我监控负责“是不是在进步”。模型对轨迹输出 0 到 1 的进度序列，也可比较两条轨迹哪条更接近同一任务目标。

如何既合并知识，又不混淆接口？SSR+

  • Scaffold：从空间脚手架起步。以 ACE-Brain-0 checkpoint 为初始化，继承跨场景、跨视角与具身空间理解，而非从零开始训练每项能力。
  • Specialize：四类任务各自学好。分别训练空间问答/规划、2D/3D grounding、具身导航和进度估计四个 checkpoint，避免训练期间彼此破坏输出习惯。
  • Reconcile：合并任务向量，而非混合原始数据。每个专家相对基础模型的权重变化被视作任务向量；作者以数据无关的优化式合并这些变化，试图保留各专家的深层表征。
  • Reactivate：重新对齐“说话方式”。合并后的模型不直接使用，而用一小份覆盖所有接口的混合 SFT 数据微调。作者认为合并通常保住了语义能力，主要丢失的是输出格式约定。

Reactivate 是相对 ACE-Brain-0 的关键增量：把“模型还会，但暂时不会按正确格式回答”变成显式可修复的问题。

动作为什么还有一条“快通路”？

  • 大主干适合慢速语义，不适合每拍控制。完整 LLM 反复前向会增加控制延迟；机械臂接触、滑动或目标偏移时，动作回路需要立刻看到最新画面。
  • DINOv3 提供最新视觉特征。轻量 Fast Vision Pathway 编码最近多视角观测，并直接注入 Action Expert，不必每次都穿过重型 LLM Decoder。
  • Action Expert 生成连续动作块。它采用 flow matching：从噪声初始化的动作逐步“流向”可执行控制序列，并同时条件化于慢速主干上下文和快速视觉特征。
  • 训练时主干被冻结。操作学习只更新快速视觉分支和动作专家，减少对空间推理、语言 grounding 等已有能力的扰动。

结果，应该怎么看？

  • 空间与 grounding 是主要增益区。作者报告相对 ACE-Brain-0，在 18 个空间感知和定位基准中有 14 个提升，符合其先强化空间底座再扩展能力的设计。
  • 统一导航模型已经有竞争力。在 RxR Val-Unseen，ACE-Brain-0.5 的成功率为 63.8%、目标误差为 4.3；导航专用版本在 R2R 可达 62.2% 成功率。
  • 操作结果依赖专门动作分支。在 LIBERO 上，采用冻结主干和训练动作专家的版本平均成功率为 98.2%；VLA 变体在 Simpler-Env Bridge 为 82.3%。这些不等于同一主干对任意真实机器人零样本控制。
  • 进度估计是很实在的闭环补全。在严格的 RBM-EVAL-Refined，ID/OOD VOC 相关系数为 0.80 / 0.88，高于文中 Robometer-4B 的 0.78 / 0.81。

“自我改进”到底改了什么？

  • 先由模型自己走出错误状态。从静态示范训练出的导航策略在闭环中执行，因而会遇到训练集未覆盖的岔路、相似走廊和错误累计。
  • oracle 负责发现偏离并接管恢复。当动作让距离变远、路径不一致、过早停下或局部误差累积时，oracle teacher 完成后续正确轨迹。
  • 失败被转成纠正示范。这些由模型自己诱发、再由 oracle 修复的状态加入训练数据；R2R 成功率由静态模仿的 48.6% 升至 57.4%，RxR 从 53.3% 升至 63.8%。
  • 在线更新的首先是外部执行状态。任务 schema、空间记忆、失败恢复案例和可复用技能可随 rollout 增量更新；模型权重更新仍需要积累并验证足够数据。

限制与开放问题

  • “统一”不等于一个网络完成全部实时控制。连续操作依赖额外的 fast vision 和 Action Expert；不同机器人本体的动作空间仍需专门适配。
  • “自我改进”仍依赖 oracle。论文没有解决真实世界中谁可靠地判错、接管和标注的问题；这正是昂贵实体机器人部署的难点。
  • 多数结论来自不同任务设置的组合。空间、导航、操作和进度评估各有不同 benchmark 与训练变体，不能把它们读成一项端到端真实世界总分。
  • 安全恢复尚未充分验证。进度分数可以触发重规划，但碰撞、抓取失败或感知幻觉下的安全边界仍需要硬件闭环实验和约束控制配合。

我的判断：ACE-Brain-0.5 最有价值的部分是 SSR+ 的问题定义：多任务合并后，模型可能不是“忘了能力”，而是“接口失配”，因此用轻量 Reactivate 重建输出约定。它也清楚地把行动和自评放入同一共享状态。更保守地看，论文的自我改进仍是一套有 oracle 的数据飞轮，而非自主进化；真正的通用物理 agent 还要跨过低层控制、在线安全与现实数据成本这三道坎。
