AHA-WAM：让世界模型慢慢规划，让机器人快速反应

Jisong Cai、Long Ling、Shiwei Chu 等 · arXiv:2606.09811 v1 · 2026-06-08

一句话结论：AHA-WAM 把机器人策略拆成两个不同节奏的系统：大型视频模型低频运行，形成可复用的长时规划上下文；较小的动作模型高频读取最新观测并输出短动作。通过解决“旧规划与新现场不一致”的问题，它在 RoboTwin 达到 92.80%，动作回路从 Fast-WAM 的 5.26 Hz 提升到 24.17 Hz；蒸馏版达到 56.95 Hz。

先补背景

  • WAM 同时学习世界与动作。世界动作模型（World-Action Model）既学习画面如何随动作变化，也学习机器人应当怎么动；视频监督给策略补充物理常识。
  • 闭环控制意味着不断重看现场。机器人执行一点动作，就用新画面和关节状态修正下一步。更新越慢，越容易对已经变化的世界做出过时反应。
  • 动作与规划不需要同一时间尺度。“把毛巾折好”是长时目标，而手指位置和夹爪力度需要快速纠正。一个模型用同样节奏处理两者，会浪费计算。
  • KV 缓存是 Transformer 的工作记忆。它保存历史 token 的 key/value 表示，让模型复用过去计算，而不用每次从头处理全部历史。

问题：同步 WAM 把两只时钟绑死了

  • 视频分支被迫关注相邻帧的小变化。短时间内画面高度相似；昂贵的视频模型花大量容量预测冗余细节，却没有把视野拉到更远。
  • 动作分支又被视频计算拖慢。机械臂需要根据接触、滑动和偏差快速修正，但同步结构只能等待世界模型完成同一轮计算。
  • 直接异步会产生“陈旧计划”。规划器算一次、执行器用多次固然快，可机器人已经移动，旧上下文可能与最新画面对不上。

设计变化不是简单删掉视频模型，而是把它移出每次动作更新的关键路径。

核心架构：低频 Planner + 高频 Executor

  • 视频 DiT 充当世界规划器。它由 Wan2.2-5B 初始化，观察更长的 64 步时间范围，产生每层可复用的规划 KV 上下文。
  • 动作 DiT 充当执行器。约 10.2 亿参数的动作专家每次生成 16 步动作块，直接接收最新本体状态，并通过联合注意力读取规划上下文。
  • 两个分支仍然联合训练。总目标是 L = L_action + λL_video，两项均使用 flow matching；测试时不解码未来视频。
  • 规划计算被多次动作更新分摊。一次昂贵的视频 DiT 前向可以服务多个动作块，视频模型不再卡住高频控制回路。

三个机制让异步真正可用

  • OVCR 用最新画面改写旧上下文。32 个轻量查询先压缩当前视觉，再从规划 KV 中找出相关内容，并用带门控的残差更新生成本动作块专属上下文。
  • 随机时间偏移训练消除“对齐依赖”。训练时将动作块起点随机平移 δ∈[0, hₐ)，让执行器学会在规划周期的任意相位读取上下文。
  • 滚动 KV 记忆保留已发生的事情。FIFO 记忆跨规划刷新保存最近历史，例如物体被移动或子目标已完成，避免每次规划只看当前一帧。
  • 三者解决不同问题。记忆负责“别忘过去”，OVCR 负责“对准现在”，偏移训练负责“适应不同时间位置”。

速度还来自系统优化与蒸馏

  • CUDA 优化把 10 步采样压到 41.37 ms。作者使用 TensorRT、CUDA Graph，并移除循环内重复计算和缓冲区复制；PyTorch eager 原本需要 415.77 ms。
  • Flash 版把 10 步去噪蒸馏成 2 步。ODE 蒸馏让学生直接接近教师最终动作，将延迟进一步降到 17.56 ms。
  • 架构收益与工程收益应分开看。异步设计移除了视频 DiT 的关键路径；24.17 Hz 和 56.95 Hz 还依赖专门 CUDA 部署与蒸馏。

结果怎么读？

  • RoboTwin 平均成功率为 92.80%。干净场景 93.40%，随机场景 92.20%；比无机器人预训练的 Fast-WAM 高 0.97 个百分点。
  • 它略高于有大规模机器人预训练的 LingBot-VA。后者平均 92.20%，但 0.60 点差距很小，不宜解读为压倒性领先。
  • Flash 用少量性能换极低延迟。两步蒸馏版 RoboTwin 为 90.20%，比完整模型低 2.60 点，但速度超过两倍。
  • 真实机器人四任务平均成功率为 78.33%。任务包括折毛巾、整理桌面、准备豆浆和收盘子；Fast-WAM 为 68.33%，π0.5 为 76.67%。
  • 真实任务比较并非“零机器人预训练”。为稳定且公平部署，AHA-WAM 与 Fast-WAM 都先在 RoboCOIN 子集的 24,600 条、约 165 小时机器人轨迹上预训练，再用各任务约 120 条示范微调。

相对前作的新意

  • 相对 Fast-WAM，它不只跳过未来视频。Fast-WAM 每个动作更新仍运行视频骨干；AHA-WAM 将视频骨干低频化，并复用其逐层上下文。
  • 相对 AsyncVLA，它把异步嵌进 WAM 内部。慢支路不是单纯给语义提示，而是真正学习长时视觉动力学，并逐层参与动作注意力。
  • 相对同步 Joint WAM，它承认时间抽象不对称。世界规划适合长范围、低频率；物理纠偏适合短范围、高频率。

限制与开放问题

  • “Horizon-Adaptive”不是在线选择时域。模型并不会测试时自动决定看多远；64 步规划、16 步动作等仍是人工设置的时间超参数。
  • 模型更大而不是更轻。完整实例约 72.3 亿参数，其中记忆与路由模块约 12.2 亿；效率来自异步调度，而非减少总参数。
  • 专用硬件优化影响速度结论。若没有 TensorRT、CUDA Graph 或 RTX 5090D，实际频率可能明显不同。
  • 长时优势尚未被专门基准充分验证。RoboTwin 多数任务为短到中程，作者也承认需要专门的长时规划测试。
  • 真实世界样本仍有限。四个任务、每项 30 次测试能说明可部署性，但不足以证明跨机器人、跨场景的普遍优势。

我的判断：这篇论文最有价值的地方，是把“世界模型应该多聪明”与“控制回路必须多快”从同一个计算预算里解耦。它像机器人版的 System 2 / System 1：慢系统规划、快系统反应。论文对上下文过时问题的处理很完整，但最高频率既是算法成果，也是重工程优化成果。
